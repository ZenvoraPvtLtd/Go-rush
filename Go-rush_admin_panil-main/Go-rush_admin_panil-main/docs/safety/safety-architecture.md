# Safety Architecture

## Overview
The Phase 9 Safety Architecture provides a secure, privacy-first mechanism for customers to share their active ride location with trusted contacts via a mock WhatsApp integration.

## Token Security Model
1. **Creation:** A high-entropy 32-byte tracking token is generated by the native `crypto` module.
2. **Storage:** Only the SHA-256 hash of this token is stored in the database within the `RideShareSession` record. This protects against database leaks.
3. **Public Exchange Boundary:** A tracking viewer submits the raw token to `POST /v1/public/ride-share/exchange`. The server hashes it, validates the active session status/expiration, and issues a short-lived `viewerToken`.

## State & Revocation
- **State Machine:** PENDING -> ACTIVE -> REVOKED/EXPIRED/COMPLETED.
- **Revocation:** The customer can stop sharing at any time. This sets the session to `REVOKED`, instantly dropping the viewer's authorization to request any further state.

## Flutter Implementation
- `SafetyScreen` displays a list of active shared sessions and allows revocation.
- `ShareRideSheet` collects explicit consent from the customer before generating the token.
- **Mock GPS Boundary:** In `RealtimeService.dart`, fake driver movement is strictly contained inside a `kDebugMode` condition to prevent any fake coordinates from leaking into a production release.
